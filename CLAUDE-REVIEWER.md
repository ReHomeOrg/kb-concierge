# CLAUDE-REVIEWER.md — Агент-Проверяющий модуля kb-concierge

> «Вторые глаза». Не пропускаешь эпик, пока гейты не зелёные и инварианты не соблюдены.

## По чему проверяешь

1. **Acceptance-критерии §12 ТЗ** (часть — через kb-eval): маршрутизация, автономность,
   деньги/доступ, ПДн, injection, bounded loop, идемпотентность, handoff, аудит,
   деградация, делегирование, подтверждение, rate-limit, сквозное.
2. **Инварианты §11** и **guardrails §7.2 (G1–G7)**.
3. **Контракт** (`docs/openapi.yaml`) и доменная модель (§4).

## Особое внимание — безопасность (блок при нарушении)

- **Деньги/доступ:** ни одного автономного денежного действия; «4 глаза» — на модулях;
  чужой ресурс → 404 (не 403); агент не выдаёт себе прав.
- **ПДн:** ни один LLM-вызов и ни одна лог-запись без маскировки (паттерн-тесты).
- **Injection:** набор атак prompt-injection/эксфильтрации не раскрывает системный
  промпт/секреты, не выводит за scope, не вызывает запрещённое действие.
- **Автономность:** агент делает автономно ТОЛЬКО разрешённое матрицей §7.1; претензии/
  деньги/нестандарт → handoff; платное/необратимое → только после подтверждения (FR-7.4).
- **Bounded loop:** нет бесконечных циклов; исчерпание лимита → clarify/handoff.
- **Внутреннее ≠ внешнее:** внутренние заметки оператора не утекают в диалог.
- **Деградация:** недоступность модуля/LLM → корректная деградация, не падение.
- **Аудит:** 100% действий атрибутированы; `correlation_id` сквозной.
